# 시술 카탈로그와 화면 흐름

## 데이터 갱신

원본은 프로젝트 상위 `data/시술설명.csv`와 `data/*_eng.png`입니다. macOS에서 `npm run data:import`를 실행하면 아래 파일을 갱신합니다.

- `src/data/treatments.generated.json`: 시술 30개, 옵션 124개, FAQ 115개. 원문과 SHA-256을 함께 보관합니다.
- `public/images/treatments/*.jpg`: 영문 PNG를 웹용으로 최적화한 이미지 30개.
- `public/images/treatments/sources.json`: 원본 PNG와 출력 이미지의 대응표.

파일명의 한글 조합형/완성형 차이는 가져오기 스크립트에서 정규화합니다. 시술 ID와 이미지 초점은 `scripts/import_treatments.py`에, 검토한 고민 분류와 출처는 `src/data/treatmentClassification.json`에 있습니다. [분류표와 근거](treatment-classification.md)를 참고하세요. 고민 태그는 탐색·정렬용 메타데이터이며, CSV에 없는 중증도별 적합성은 생성하지 않습니다.

상세 설명은 모든 UI 언어에서 한국어 원문을 사용하고, 추천 카드 요약은 검토한 분류 정보를 사용합니다. 이전 카탈로그 번역이 새로운 데이터를 덮어쓰지 않습니다. 가격 범위는 옵션별 최종 표시 가격을 기준으로 계산하고 정가와 VAT 표시는 상세 화면에서 구분합니다. CSV에는 병원별 견적이나 해당 시술 제공 여부가 없으므로, 병원 화면의 가격은 상담 후 확인으로 표시합니다.

## 이동 흐름

홈 → 진단 시작 → 카메라 → 분석 → 피부 점수 → 추천 시술 → 시술 상세 → 추천 병원 → 예약 선택 → 후기 열람 요청 → 회원가입 → 요청한 시술의 후기 목록.

- 카메라에서 기본정보를 수정할 수 있습니다.
- 시술 탐색과 예약 선택에는 회원가입을 요구하지 않습니다.
- 커뮤니티 메뉴와 상세·예약 화면의 후기 버튼은 동일한 가입 조건을 적용합니다.
- 가입 취소 시 원래 화면을 유지합니다. 가입 완료 시 요청했던 후기 필터를 유지합니다.
- 해당 시술의 후기가 없으면 빈 목록과 전체 후기 이동 버튼을 표시합니다.

## 현재 구현 범위

GitHub Pages용 프런트엔드입니다. 회원가입은 현재 방문의 상태만 변경하며 계정 서버, 이메일 인증, OAuth는 연결되어 있지 않습니다. 예약 선택은 병원으로 전송되지 않습니다. 화면에 이 체험 범위를 안내합니다. 비회원에게 후기 내용을 렌더링하지 않지만, 실제 비공개 후기를 보호하려면 서버 측 인증과 접근 제어가 필요합니다.

## 검증과 실행

- `npm run build`: TypeScript 검사 및 프로덕션 빌드.
- `npm test`: Node의 모듈 훅과 기존 TypeScript/React 의존성을 이용한 12개 테스트. Node 25.8.2에서 확인했습니다.
- `npm run dev`: 로컬 미리보기.

테스트는 가입 전후 이동, 취소, 시술별 후기 필터 보존, CSV 및 언어별 데이터 연결, 가격 범위, 영문 이미지 경로, 주요 화면 서버 렌더링을 검사합니다. 실제 브라우저와 카메라 동작은 별도 확인이 필요합니다. 이번 환경에서는 로컬 서버의 포트 바인딩이 제한되어 브라우저 검증을 실행하지 못했습니다.

변경 내용은 로컬 작업 폴더에만 있으며, GitHub Pages 배포는 하지 않았습니다.
